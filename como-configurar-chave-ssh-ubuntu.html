Como Configurar Autenticação por Chave SSH e Desativar Login por Senha no Ubuntu

Publicado em 15 de Outubro de 2026 | Por José Ronaldo | Categoria: SysAdmin / Segurança
[ Espaço reservado para anúncio do Google AdSense - Topo do Artigo ]

Ao expor um servidor Ubuntu para a internet na porta padrão (22), ele se torna alvo instantâneo de botnets automatizadas executando varreduras de dicionário e ataques de força bruta (*brute-force*). Se o seu servidor aceita autenticação via senha tradicional, a segurança de toda a sua infraestrutura passa a depender unicamente da complexidade dessa senha.

A substituição do acesso por senha pela autenticação por chave pública SSH é o passo elementar na rotina de *hardening* (endurecimento de segurança) em qualquer ambiente de produção Linux. Neste guia prático, você aprenderá a gerar pares de chaves criptográficas, exportá-las com segurança e bloquear totalmente os acessos por senha sem correr o risco de perder a conexão com o servidor.

Como Funciona a Criptografia Assimétrica do SSH

A autenticação por chave SSH baseia-se em um par de chaves criptográficas assimétricas:

  • Chave Privada: Permanece armazenada na sua máquina local de trabalho. Ela é secreta e nunca deve ser enviada pela rede ou compartilhada.
  • Chave Pública: É copiada para o servidor remoto no arquivo ~/.ssh/authorized_keys. Qualquer pessoa pode ver a chave pública sem que isso comprometa a segurança.

Quando você solicita a conexão, o servidor desafia sua máquina local usando a chave pública. A máquina local responde provando que possui a chave privada correspondente. Se a matemática criptográfica bater, a sessão é liberada sem que nenhuma senha trafegue pela rede.

Passo 1: Gerando o Par de Chaves na Máquina Local

Acesse o terminal do seu computador de trabalho (Linux ou macOS). Para máquinas Windows, utilize o PowerShell ou o WSL.

Atualmente, o algoritmo recomendado para geração de chaves é o Ed25519, por oferecer maior velocidade e segurança superior com chaves menores em comparação ao clássico RSA.

Execute o seguinte comando para gerar o par de chaves:

ssh-keygen -t ed25519 -C "seu_email@exemplo.com"

Nota: Caso esteja interagindo com sistemas legados que não suportam Ed25519, utilize o algoritmo RSA com pelo menos 4096 bits:

ssh-keygen -t rsa -b 4096 -C "seu_email@exemplo.com"

Durante a execução, o terminal exibirá duas perguntas:

  1. Local para salvar a chave: Pressione Enter para aceitar o caminho padrão (geralmente ~/.ssh/id_ed25519).
  2. Frase de segurança (Passphrase): Digite uma frase secreta. Ela funciona como uma senha para descriptografar sua chave privada local. Recomenda-se definir uma *passphrase* para evitar acessos não autorizados caso seu computador físico seja comprometido.

Passo 2: Copiando a Chave Pública para o Servidor Ubuntu

Com o par de chaves criado localmente, precisamos enviar a chave pública para o servidor remoto. Existem duas maneiras de realizar esse procedimento:

Método A: Utilizando o utilitário ssh-copy-id (Recomendado)

O utilitário ssh-copy-id automatiza o processo de criação do diretório remoto e ajuste das permissões de arquivos. Substitua o usuário e o IP pelos dados do seu servidor:

ssh-copy-id usuario@ip_do_servidor

O sistema solicitará a senha do usuário remoto pela última vez para instalar a chave pública. Ao término, você verá uma mensagem confirmando que a chave foi adicionada.

Método B: Adição Manual via Terminal

Se a ferramenta ssh-copy-id não estiver disponível no seu sistema local, você pode ler o conteúdo da sua chave pública e gravá-lo no arquivo do servidor via conexão SSH:

cat ~/.ssh/id_ed25519.pub | ssh usuario@ip_do_servidor "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

Passo 3: Testando a Autenticação Sem Senha

Antes de alterar qualquer configuração de segurança no servidor, abra uma **nova janela de terminal** na sua máquina local e tente conectar-se:

ssh usuario@ip_do_servidor

Se você definiu uma *passphrase* no Passo 1, o sistema pedirá a frase da chave. Caso contrário, o login será efetuado instantaneamente sem solicitar a senha do usuário do Linux.

Atenção Crítica: Não feche a janela de terminal original onde você já está logado como root ou sudo no servidor até concluir e validar o último passo deste guia.

Passo 4: Desativando o Login por Senha no Daemon do SSH

Agora que a chave pública está funcionando perfeitamente, podemos alterar a configuração do OpenSSH para rejeitar qualquer tentativa de login que utilize senha tradicional.

Conectado ao servidor Ubuntu, abra o arquivo de configuração sshd_config utilizando o editor de sua preferência:

sudo nano /etc/ssh/sshd_config

Localize as seguintes diretrizes dentro do arquivo (utilize `Ctrl + W` no editor Nano para buscar):

  1. Procure por PasswordAuthentication. Remova o caractere `#` do início da linha (se houver) e altere o valor para no: 
    PasswordAuthentication no
  2. Certifique-se de que a diretriz PubkeyAuthentication esteja configurada como yes: 
    PubkeyAuthentication yes
  3. (Opcional) Para evitar logins diretos como superusuário, configure a diretriz PermitRootLogin para proibir o acesso de root via senha: 
    PermitRootLogin prohibit-password

Salve o arquivo (`Ctrl + O` e `Enter`) e saia do editor (`Ctrl + X`).

Passo 5: Testando a Configuração e Reiniciando o Serviço

Antes de reiniciar o serviço do SSH, valide se não foram introduzidos erros de sintaxe no arquivo de configuração:

sudo sshd -t

Se o comando não retornar nenhuma saída no terminal, a sintaxe está correta. Reinicie o serviço do OpenSSH para aplicar as alterações:

sudo systemctl restart ssh
Dica de Ouro: Mantenha sua sessão atual aberta. Abra uma **terceira janela de terminal** local e tente fazer login. Para testar o bloqueio de senha, force uma tentativa informando um arquivo de chave inexistente: 
ssh -o PubkeyAuthentication=no usuario@ip_do_servidor
A resposta esperada no terminal é o erro de acesso negado: Permission denied (publickey).

Ajuste de Permissões no Servidor Linux

Se após os passos acima a autenticação por chave falhar e solicitar a senha, o motivo mais comum é o incorreto ajuste de permissões da pasta .ssh no servidor. O SSH é rigoroso e recusa chaves se as permissões forem muito abertas.

No servidor, execute os comandos de correção de permissões no diretório do usuário:

chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
chown -R $USER:$USER ~/.ssh

Conclusão

Com a autenticação por chave configurada e o login por senha desativado, seu servidor Ubuntu está protegido contra a imensa maioria das varreduras automatizadas que ocorrem na porta 22. O próximo passo recomendado na rotina de *hardening* é a instalação do Fail2ban para bloqueio de IP e a alteração da porta padrão do SSH.
